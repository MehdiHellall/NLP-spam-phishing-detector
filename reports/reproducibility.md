# Reproducibility Report

Last updated: 2026-08-04

## Scope

This report separates committed, reproducible project state from historical notebook findings. No model score is treated as reproduced unless it is generated by the CLI/package workflow and saved as a durable artifact under `reports/metrics/`.

## Reproducible Script Results

End-to-end training and evaluation artifacts are committed under `reports/metrics/`.

The package does include scriptable pieces needed for reproducible runs:

- CSV loading and label normalization in `email_threat_detector.data`.
- Null, empty-text, and exact-row cleanup in `email_threat_detector.cleaning`.
- Duplicate-text conflict auditing and removal in `email_threat_detector.duplicates`.
- Deterministic balanced sampling in `email_threat_detector.sampling`.
- Stratified train/validation/test splitting and text-overlap detection in `email_threat_detector.splits`.
- Leakage-safe sklearn TF-IDF pipelines in `email_threat_detector.models`.
- Stable classification metric helpers in `email_threat_detector.metrics`.
- CLI commands in `email_threat_detector.cli` for baseline training, transformer split preparation, and transformer fine-tuning.

The most important leakage fix is the package-level preparation flow: conflicting normalized texts are removed, duplicate normalized texts are deduplicated before splitting, and split boundaries can be checked with `assert_no_text_overlap`.

The real baseline runs used:

```powershell
email-threat-detector train-baseline --data-path <kaggle-cache>\df.csv --reports-dir reports --model-name tfidf_logreg
email-threat-detector train-baseline --data-path <kaggle-cache>\df.csv --reports-dir reports --model-name tfidf_complement_nb
```

Both commands wrote metrics JSON under `reports/metrics/` and confusion matrices under `reports/figures/`.

| Model | Test accuracy | Test macro F1 |
| --- | ---: | ---: |
| TF-IDF + Logistic Regression | `95.76%` | `95.76%` |
| TF-IDF + ComplementNB | `91.37%` | `91.32%` |

The transformer command was run with the compact pretrained checkpoint `google/bert_uncased_L-2_H-128_A-2` on the same prepared split logic:

```powershell
email-threat-detector prepare-transformer-splits --data-path <kaggle-cache>\df.csv --output-dir data\processed\transformer_full
email-threat-detector train-transformer --split-dir data\processed\transformer_full --output-dir artifacts\transformers\bert-tiny --metrics-path reports\metrics\bert_tiny_transformer_metrics.json --model-name google/bert_uncased_L-2_H-128_A-2 --epochs 1 --batch-size 64 --max-length 128
```

| Model | Test accuracy | Test macro F1 |
| --- | ---: | ---: |
| BERT Tiny transformer | `95.09%` | `95.08%` |

## Known Limitations

- The current tests do not train large models or reproduce notebook headline metrics.
- The raw dataset and model artifacts are not committed.
- The original notebook cleanup dropped exact duplicate rows, but did not enforce normalized text deduplication before splitting.
- The dataset is public but can still contain sensitive message text, identifiers, URLs, or harmful phishing content.
- Accuracy alone is not sufficient for a security-sensitive classifier; macro F1, per-class recall, confusion matrices, calibration, false-positive review, and adversarial testing are still needed.
